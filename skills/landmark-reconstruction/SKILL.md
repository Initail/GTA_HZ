# 杭州实景地标重建

首次应用时说明正在使用本 Skill。当前项目是 GTA_HZ「杭城之行」，参数源为 `config/cities/hangzhou.json`。先读 [研究入口](../../docs/RESEARCH.md)、[重建指南](../../docs/REBUILDING.md) 和目标 job/spec/evidence，核对该对象真实身份与最新阶段。上游深圳工作流只作契约参考，不执行其中默认城市、作者路径或模型指定。

## 证据契约

1. 明确对象 ID、真实园区/地块/楼群、范围和独占写入者。身份未确认则保留 blocker，继续独立可做工作。
2. 固定 OSM、地形和建筑资料的 URL、快照/观察日期、坐标系、许可与 SHA256。优先政府、设计方、业主/运营方及多方向照片。
3. 记录足印、楼栋数量、朝向、高度、轮廓、屋顶、退台、连桥和入口。区分 `measured`（方法）、`reported`（原始来源）、`estimated`（估计方法/误差）、`unknown`，保留矛盾证据。
4. 照片默认仅参考，未授权不能作为发布贴图。30m DSM 插值不会产生更高实测精度，山体不能用单个椭球冒充。
5. 在目标 `evidence.json` 和 `spec.json` 完成依据，再用 `scripts/landmark_tasks.py check --job <job.json> --stage evidence-ready` 执行门槛。保持失败证据。

任务包状态、哈希字段与交付格式见 [原契约参考](../../docs/landmarks/agent-workflow.md)。当前杭州任务包的选择和可执行命令以 [REBUILDING](../../docs/REBUILDING.md) 为准，不默认生成深圳对象。

## 建模边界

在新的 `artifacts/` 候选目录制作一个对象，优先完成可辨识主体，再做立面、材质、招牌与夜景。普通体块只是中间稿。对象模块放 `scripts/landmarks/`，使用共享网格 API；`scripts/city_mesh.py` 导入会初始化 Blender 场景和材质，不能用普通 Python 导入检查数据。

WGS84 原点 `[120.155,30.274]`，经/纬换算系数读取配置，统一地理缩放 `0.60`。原始地理/建筑米数只缩放一次，既有游戏单位人物、车辆与虚构内景保持尺寸。Blender 东/北/上 → GLB Y-up → Babylon，保留现有根节点方向处理。GCJ-02/BD-09 和旧研究投影不能直接当 WGS84。

只写获分配模块和候选；共享世界、总 GLB、排除列表、配置及资源锁由主集成人员串行修改。独立对象可并行，重型 Blender 与浏览器 GPU 检查单并发。

## 集成与验收

每次候选交付包含源码/输入/GLB 的 SHA256、构建命令和退出结果、规格/来源、尺寸/方向/基高、资源预算及明确未通过项。先校验真实几何与地面支撑，再推进视觉阶段。

集成时同时排除基础楼体和近景立面，更新碰撞、地图、到达点、植被避让与清单。入口必须连通且无障碍。西湖/钱塘江水面进入基础水体管线，候选水面薄片不作为运行时保证。跨水/高架需要分层连接，不能把几何相交判为路口。

每个地标保存当前版本的俯视、街面、远景及昼夜实机截图，与证据对照；实测入口、碰撞、驾驶/步行到达和预算。构建成功、截图候选、历史 FPS 或 NullEngine 导入均不能替代当前资产实机验收。阶段只能在对应契约真实通过后推进。

## 本次实际修复

1. 七条固定 OSM 源步行道路进入同源路面、步行支撑、禁车和植被根部预留接口。继续使用杭州原点与 0.60 的既有游戏坐标，不再缩放人物、车辆或这些已经缩放的顶点。
2. 首次实机发现路面不可见，查明两项独立问题：原数值地面与实际 GLB 三角面之间存在厘米级差异；直接生成的 Babylon 路面误用了 GLB 镜像后的绕序。分别修复，没有关闭背面剔除来掩盖错误。
3. 从实际交付的两块 terrain GLB 解码三角面，裁切原步道范围，生成一份同时供物理与显示使用的路面和局部地面补丁。旧地形 GLB 字节不变。旧地形部分共享边高差最大 0.0256066g，共享顶点以两侧高度中点缝合，最大校正 0.0128033g。石板面在同一补丁之上 0.015g，独立接地容差仍是原定的 −0.001g 至 0.03g。
4. 为避免全球坐标转 Float32 后出现零面积细缝，水平拓扑统一到本范围 Float32 的 2^-12g 网格；具体足印面积和 Hausdorff 误差保存在 `fit-report.json`。这是可量化的渲染精度处理，不是新的实测地形。原观测来源仍为 30m DSM，路宽与石板厚度仍是明确估计。
5. 添加原创 128×128 石板拼缝纹理，共享材质、MipMap、纹理和几何释放；不使用参考照片做贴图。近邻九个固定植物布点的十二个实际原型/LOD 均通过保守外包半径检查，最小间距 0.8212349g，没有搬移或删除树木。

- `site-path-regression-v2.json`：14 项既有场地/权限/上下层/结构板/水域边缘检查通过，0 skipped。城市专属对照仍完整检查原基线、休闲增量及新增路径的各自内容，不删除旧断言。
- `site-path-types-v3.json`：场地和路径规划纯模块严格类型通过。`bundle-full-v12.json`：当前完整入口预览打包通过，8.2MiB JS、86.4KiB CSS，峰值子进程 211,856KiB；**不是正式 Vite 构建或完整类型图通过**。
- `site-path-render-contact-v5.json`：对实际地形三角面的 7,672 个顶点、边中点、重心采样，路面间隙 0.0069204–0.0278033g，0 埋入、0 超限悬空、0 缺失支撑。
- `loader-probe-v14/route-preflight-result.json`：1,714 个路线点，每点原版 0.23g 半径九点碰撞检查；0 墙体/水域阻挡、0 超过原 0.48g 台阶规则、0 禁车失效。两处原版 `CityWalk` 一秒前进各约 1.6g；这是离线回放，不是实机走完路线。
- `loader-probe-v12` 首次真实局部实机记录埋路和入口视野问题，保持视觉失败。`loader-probe-v14` 证明指定日间近景路面恢复可见，实际前进 1.61312g；其夜景点击晚于 25 秒截止，名为 `lingyin-approach-night.jpg` 的图片是释放后的空画布，**不能作为夜景证据**。

- `loader-probe-v10` 道路类型接错，未创建引擎即失败；`loader-probe-v11` 解码器因 `.cjs` 被错误标为 `application/octet-stream` 加载失败。已修正诊断服务器 JavaScript MIME，保留 `nosniff` 与哈希白名单，并验证整城端点仍返回 404。
- 原路径贴数值地面的接地失败、初版缝合/精度失败、背向路面回归的红灯结果均保留。`site-path-regression-v1.json` 在旧城市大数组对照失败路径触发 256MiB 资源上限，采样峰值 1,163,024KiB；已终止自有测试进程。修正增量对照并以内容哈希报告差异后，14 项全部检查在 120,256KiB 内通过。没有放宽资源线或步行/接地容差。

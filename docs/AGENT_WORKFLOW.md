# 多 Agent 协作与交接

## 领取任务

主集成人员维护共享世界、城市配置、清单与资源锁。每个独立对象/模块只有一个写入者。其他 Agent 可以并行调查来源、编写互不冲突的对象模块、审查或运行轻量 CPU 检查；重型 Blender 和浏览器 GPU 验证串行排队。

每项任务在 Issue/PR 中给出以下契约：

```text
目标与可观察完成条件：
基线提交 / 资源锁 SHA256：
允许修改的文件 / 对象 ID：
只读共享输入：
独立候选输出目录：
必须保留的行为：
验证命令与真实场景：
当前 blocker / 负责人：
```

## 修改与集成

1. 从当前主线建立独立分支。先记录基线测试和相关失败，不复制某个历史 pass 作为结果。
2. 地标任务使用 [实景建模 Skill](../skills/landmark-reconstruction/SKILL.md) 的 evidence → model → visual → integrated 阶段和哈希契约。照片估计与实测分开，身份不明的对象保留 blocker。
3. Worker 只写自己的模块和候选。向集成人员提交规格、来源/许可、模型、哈希、命令、截图和未通过项，不直接覆盖总 GLB 或共享清单。
4. 集成人员串行核对基础楼/近立面排重、坐标、碰撞、导航、到达点、植被和运行资源清单，再执行受影响回归与实机检查。
5. PR 说明最终行为、验证范围和风险。合并后更新 [状态](STATUS.md)、[变更记录](../CHANGELOG.md) 和相应文档入口。

## 交接完成条件

下一位 Agent 能从同一提交、同一资源锁运行命令，找到实际输入和失败证据。交接应写出「下一项可执行动作」，不能只有“继续优化”。若未完成，保留失败、输入 SHA 和最小复现；记录尚缺授权/身份/资产/实机条件，继续可独立推进部分。

上游 [agent-workflow](landmarks/agent-workflow.md) 保留详细任务器参考，其中历史作者路径、深圳坐标、指定其他模型和派工授权仅是历史上下文，不约束本仓当前任务。

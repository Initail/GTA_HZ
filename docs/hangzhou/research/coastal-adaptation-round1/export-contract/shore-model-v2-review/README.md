# 四段岸线 v2 独立复核（2026-11-11）

结论：源线、干侧实体、闭合拓扑、朝向、导出三角面和 UV 的有限 CPU 复核通过；**城市阳台段存在实际三维结构相交，不可集成验收**。其他三段可以作为独立的几何候选继续串行接入，但没有获得所有城市设施、碰撞、视觉或性能验收。

## 绑定范围与方法

输入是固定 OSM 证据包、`render-input-v6`、`shore-meshes-v2`、实际 `shore-glb-v2/coastal-shoreline.glb`，以及仍在中性 baseY=0 的 `city-balcony-v1`。见 `input-bindings.json`。所有 producer 输入哈希一致。实际岸线 GLB SHA256 `39e4eb81d587d35ce98ba533bd64228d0c9678e9362e2c068508e024266c1340`。

本审查没有调用 Blender、浏览器、producer 的 Surface 实现；独立以 GEOS 线投影/STRtree 和三角地形线性方程计算地面。以 stdlib 解码 GLB accessor/node TRS，转回游戏 ENU。另实际运行项目 `check_hangzhou_closed_glb.mjs`，结果保留为另一层证据。

## 几何与导出

4 个 NPZ 和 GLB 均无零面积三角面；每条几何边恰有相反方向的两个邻面。所有顶面朝上，底为水面0.9g减0.3g，所有顶点高于该估计水面。GLB 的有向三角面集合与独立算出的 local float32/ENU 往返结果**逐值完全一致**，未加水面、道路或平台面。4 个材质分别为 `seawall / land / land / land`；未把后三段水界伪称混凝土墙。

实际 UV 全部有限，所有 UV 三角面均非零面积；法线有限。本文验证数据完整性，不把它升级为材质视觉效果验收。坐标方向保持 ENU → glTF(x,up,-north)，node translation 被正确应用；没有再次0.60缩放。

float32 实际 GLB 的岸线最大平面偏移0.000066692g，导致整段累计约0.009804/0.003466/0.003300/0.003433g² 的微小水侧投影；这是记录在案的序列化量化，不应写成“GLB严格零入水”。见 `serialized-boundary.json`。

## 高度声明纠正

所有顶点对独立 ground 的误差 <1e-14g。但沿每条前/背缘细分段的7个内部位置采样，并不能得出顶面始终低于连续地面：

| 对象 | 前缘最大绝对误差(g) | 背缘最大绝对误差(g) |
|---|---:|---:|
| 滨江有源挡墙 | .006024 | .006107 |
| 城市阳台 | .010997 | .011365 |
| 奥体 | .006631 | .006776 |
| 滨江公园 | .004590 | .004774 |

城市阳台背缘最高 +.011365g。producer 以中点阈值 .01g 自适应，未对整个连续区间及背缘保证此阈值。因此原 manifest 的 `below local ground, no new above-ground obstacle` 过强；应记为沿当前估计地面离散拟合、未另加碰撞，最终接缝待验。该厘米级误差本身不要求删除几何，但不是严格“无突出”的证据。

## 城市阳台：确定的三维冲突

独立对实际 GLB 做 XY broad phase，再做三维边-面/重心窄相交，位置容差1e-6g。不是仅比较包围盒。

| 城市阳台材质 | 相交三角面对 | 不同阳台面 |
|---|---:|---:|
| concrete | 467 | 41 |
| darkglass | 88 | 19 |
| landmarkglass | 88 | 36 |
| roof | 43 | 4 |
| steel | 150 | 75 |

共836对。源上层公共地板足印与岸实体重叠 **8.922897503g²**。411 个落在此公共足印的岸顶样点，比当前上层地板3.6g高 **.032699–1.359128g**。岸实体穿过地板、玻璃、扶手，不是可忽略的边界接触。例：屋面交点 ENU `[3372.6628418,-1905.6912842,3.5999999]`。原始面编号和交点在 `city-balcony-actual-3d-intersections.json`；公共地板样本在 `city-balcony-upper-deck.json`。

该结果绑定当前 `city-balcony-v1` 的 baseY=0。绝对楼坪本来未落定，因此应先解决楼坪、两条有源接近 finger、局部岸线/建筑所有权与高度感知碰撞；不能通过删除整岸或填满下层公共空间掩盖问题。阳台岸段目前隔离保存。其余三段距实际阳台足印分别3384.459/688.322/1668.127g，排除了与本对象的碰撞，**不代表它们与所有其他对象均无冲突**。

## 审查工具边界与保留失败

初次 `check.log` 在 NumPy 新版不接受2维 cross 时失败；修为显式2维行列式后成功，旧日志保留。`geometry.json` 中 `rounded1mmTriangleSetsEqual=false` 是先逐点 round(3) 遇到跨舍入边界造成，不是几何漏面；不用它判通过。改用独立精确 float32 有向三角面集合，四项均 true，见 `exact-float32-independent.json`；项目实际 checker 也全部通过。没有删除失败或补写假 pass。

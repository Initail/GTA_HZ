# 杭州之门第二轮：源足印与外观候选

本轮得到可以开始主体候选的证据，已交付独立 B API 模块；尚无 GLB 和实机验收，不是地标最终完成。

## 固定地理证据

采用主集成固定的 Geofabrik 浙江 261011 快照，OSM 时间 `2026-10-11T20:21:06Z`，PBF SHA256 `4eb65f64925498408faeee7eb04b60d7eb8a01c49ddb239f73070d4d282c75a9`。本目录保存三要素的精确子集，并和 OSM 原站辅助快照逐顶点对照：三组坐标一致，只有闭环起点/顺序可不同。原站快照保留 way/node 版本与编辑时间。

| 项目 | 本轮值 | 证据性质 |
| --- | --- | --- |
| T1 西塔 | way 1015040645；质心 `[120.23220650769576,30.22934883006455]` | 从 OSM 足印算出的面积质心，不是实地入口点 |
| T2 东塔 | way 1015040647；质心 `[120.2329069500585,30.230140871111367]` | 同上；东/西塔功能与华东院供稿对应 |

量测采用 WGS84 椭球在本地纬度的东西/南北米系数及面积质心。建模时使用共享 `scripts/city_config.py` 的杭州配置，几何重新从 WGS84 投影；这两个场景的投影角色区别已保留，局部研究米系数不会复制为另一套城市配置。规划误差允许值 ±5 m 和 ±3° 只是候选容差，来源误差未经实地验证，不能称统计置信区间。

## 形体依据与估计范围

[华东院官方供稿](https://www.thepaper.cn/newsDetail_forward_21768064) 报两塔 310 m、宴会厅楼层 22 m、花园 34.6 m、幕帘最高/最低 103.600/53.381 m、悬垂跨度约 60 m。正文称 63 个地上楼层，[SOM 项目页](https://www.som.com/projects/greenland-hangzhou-century-center/) 称 64 层；候选的 64 道立面带只表达节奏，不声称已消除计数口径差异。

已实际看过官方正外观、幕帘俯视、塔冠向北岸及 SOM 剖面示意，详见 `photo-review.md`。原始拍摄时间未知，含施工期画面。首张照片相机方位不能无歧义推定，保留 unknown；两塔轴线直接由足印确定，不依赖该相机推断。照片只在临时研究缓存计算哈希，没有打包至本目录、模型或发布贴图。

收放轮廓、斜切冠顶、幕帘横拱度、板厚和幕墙肋宽属于 `spec.estimates` 中有方法和误差的估计。候选包含双曲/悬垂镂空板块、拱形下腹、曲面双塔和幕墙节奏。没有用两个方盒或实心横杆代替主体。

## 任务阶段与复现

实际任务包在 `task-bundles/hangzhou-gate/`。本轮运行：

```sh
.venv/bin/python docs/hangzhou/research/core/gate-round2/measure_gate.py
.venv/bin/python scripts/landmark_tasks.py check --job docs/hangzhou/research/core/gate-round2/task-bundles/hangzhou-gate/job.json --stage evidence-ready --record
.venv/bin/python docs/hangzhou/research/core/gate-round2/validate_candidate.py
```

`evidence-ready` 当前实际通过范围为双塔、拱桥、幕帘的主体外观候选。完整零售裙房、入口/绿化、全侧立面、准确停机坪、夜景、碰撞/到达点/实机/性能仍 pending。`jobs/` 是系统 Python 3.8 初次生成失败的部分目录，只含未形成有效任务的证据副本；有效任务以 `task-bundles/` 为准。失败原因和换运行时的记录在 `attempts.json`。

独立模块：`scripts/landmarks/hangzhou_gate.py`，接口 `build(b,lm,spec,scale=.6)`，由共享构建器 finish/export。模块不导入 city_mesh/bpy、不清场、不输出总 GLB、不创建材质或灯、不改城市配置；恢复传入 B.frame。真实米制尺寸缩放一次，lm.x/z/y 已为游戏单位。

CPU 检查得到 8,374 faces、16,740 个导出前三角形、5 种现有材质、0 新灯。检查了有限坐标、非退化面、共享投影一致、框架恢复、310 m 总高与游戏基面一次缩放。幕帘板块是薄的闭合体，保持既有材质剔除设置时从上下两侧都可见。结果只是 B 接口记录，不能替代实际 GLB 面数、着色、GPU、碰撞或帧时检查。未启动 Blender。

## 主集成事项

1. 使用 spec.anchor 生成 lm.x/z，地面 datum 确认后以游戏单位传 lm.y；把公共 GLB 的方向处理保持原样，不再次旋转全对象。
2. 一次串行排除三要素 `way/1015040645`、`way/1015040646`、`way/1015040647` 的基础楼体与近景立面，避免叠楼。零售 way 1015040643/644 不在本候选替换范围。
3. 模块提供两塔的 `ground_footprints`；不能拿连接体外包盒封闭拱门通道。主体轻微收放及立面肋出挑要由实际碰撞/绕行核对。中央宴会厅高悬，不是地面咖啡馆。
4. 到达点仍从连通实际道路或公共可走区域选择；本轮锚点不是到达点。精确私有入口没有完成证据，不能据此提供进入办公楼玩法。
5. 在隔离候选目录实际构建、导出和预算检查，然后拍俯视/街面/远景及昼夜图；全侧立面、材料反射和屋顶线要再与参考核对。没有 GLB 时模型阶段仍停在 evidence-ready。

`research-hashes.json` 绑定本轮本地记录和源码 SHA256；它不把源照片的未知许可改成可再发布，也不把 CPU 几何检查改写为 verified。

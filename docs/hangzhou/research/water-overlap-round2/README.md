## 三个冻结决策

1. **断桥荷塘：保留身份，共用西湖水面。** `way/975870009` 的 part 0 完整位于 `relation/2308774` 的 part 0 内。荷区源足印、名称和 OSM 标签继续保存，作为荷花、围网、材质等语义区域，不另渲染一个高出 0.8991 game 的 DSM 水片。父水面沿用西湖现有 4.5 game 暂定值。政协网站转载的原始报道明确将断桥列为西湖清塘首站，并描述可抬起的荷区围网和鱼类出入；这是支持“西湖内管理区域”的 reported 证据，不是水位测量，也不是独立挡水坝证明。[杭州政协网，2024-04-16，原载都市快报](https://www.hzzx.gov.cn/cshz/content/2024-04/16/content_8716273.htm)
2. **东河船闸：闸室占有其轮廓，泛河面扣除该区域。** 保留 `way/662789923` 闸室足印，从 `way/520199008` 渲染足印扣除；两个原始源对象都保留。固定 OSM 给出四段 lock_gate 及带 `lock=yes` 的东河中心线。OSM 将 `water=lock` 定义为闸室水域，故具有明确的分区语义。[OSM water=lock 定义](https://wiki.openstreetmap.org/wiki/Tag:water=lock) **扣除结果为 MultiPolygon，不能只保留最大部分或单一 exterior。** 河段高度暂留 6.383285063645915 game、闸室 5.594986665755657 game，均仅为原有估计；闸门模型、开闭状态、上下游实测水位和动态过程仍 pending。本轮不把这个高度差解释成已证实的闸差。
3. **仓前方向带 layer=-1 的支渠：限定一个源部件的开放汇入口改编。** `way/552611348` 的南端节点 `5335086034` 与余杭塘河中心线 `way/25341148` 真正共享，北端节点 `5335086029` 与 `way/641215255` 共享。附近有明确标注 bridge=yes/layer=1 的跨渠步行桥与服务道路桥；水渠自身没有 tunnel/culvert 标签。此源拓扑支持开放连接的候选推断，但不能证明不存在未记录水工设施。`layer` 表达相对顺序，不可直接换算米数；负值也不自动表示地下。[OSM layer 定义](https://wiki.openstreetmap.org/wiki/Key:layer)

第三项采用明确、可回退的 estimated 游戏改编：仅 `way/552611233` part 0（源面积 1679.3384106582364 game²）沿用 `way/642559807` part 0 的暂定水面 **1.7648872085156757 game**；重叠区域归主河渲染，支渠渲染足印扣去主河部分。整段使用单一暂定高度，避免只修汇口后在人为补丁边缘产生台阶。它**不递归传播**到北端及其他流域对象，不删除 raw layer=-1 或原高度来源。北端衔接、纵向水面、桥下净空和真实水工关系继续 pending。完整影响范围、原值和禁止传播规则见契约。

## 可重现文件与检查

- `extract_context.py` → `layer-context.json`：固定 PBF 的局部源图、版本、时间戳、节点及桥渠标签。
- `audit_waterway_connections.py` → `all-pair-waterway-context.json`：27 组局部中心线/共享节点/控制物检查；30 game 仅为检索窗口，不是物理影响范围。未检出控制物不证明现实不存在。
- `build_decisions.py` → `decisions.json`、`geometry-dry-run.json`：冻结三项操作及独立几何检查。严格绑定 city 哈希，所有写入均在此目录。
- `sources.json`：网页来源层级与证据限度；`validation.json`、`package-manifest.json`：文件绑定和范围检查。

在项目根使用 `.venv/bin/python docs/hangzhou/research/water-overlap-round2/build_decisions.py` 重建决策。数据源未改变时无需重复读取完整 PBF。源对象保留、全局湿区、非目标高度不变、多部件/孔洞、网格和实机结果仍由主集成在隔离候选中验证。

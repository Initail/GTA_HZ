# 开发优先级与领取入口

以下顺序来自已确认需求。发布和文档工作不改变前五项的优先级。每个任务先核对 [STATUS](STATUS.md) 与对应研究证据，再写明负责文件、输入 SHA、输出目录和验收条件。

| 优先级 | 工作包 | 可观察的完成条件 |
| --- | --- | --- |
| P1 | 玩家自行车/游船/钓鱼 | 主城实际入口可用；取用/驾驶或操作/返回/结算/刷新恢复/互斥实测；单车踏频与表现补齐 |
| P2 | 西湖与灵隐实景 | 湖岸/桥面连续、殿堂而非通用高楼、寺院接地和入口可达；原子排重；当前俯视/街面/远景/昼夜与来源对照 |
| P3 | 多样 NPC 与互动 | 不同身份/外观/日常活动和可用互动；不破坏原任务；原创资产和资源预算完整 |
| P4 | 公交 | 修复剩余靠站定位；源线路、站台、信号、上下车、整线运行及保存/退出闭环实测 |
| P5 | 园区/景区通行、大门和标识 | 明确车行/步行边界、真实入口与停车导向；不可达目的地修正；碰撞和导航一致 |
| P6 | 指定其他地标 | 菜鸟、阿里 A/B/C、杭州之门、武林广场、钱江新城/奥体逐对象完成证据、模型与实机终验 |
| P7 | 长期性能与更多天气表现 | 当前硬件/浏览器的冷启动、帧时、驻留、恢复、长会话；季节效果在预算内增加 |

持续门槛：保留上游所有已实现模式、原经济参数和防重复结算；修复跨江/高架层级和不可达目标；所有公开资源许可明确。UE5 保持实验，不挤占浏览器主城优先级。

适合新贡献者：复现一个明确地点的问题并交证据、补一处地标入口指示、补一个真实夹具回归、整理一个研究对象的 measured/reported/estimated/unknown。共享 `city-world.ts`、坐标和总清单需与集成人员协调。
